Spacing & padding

scale · gap ladder · component padding · controls · tables · radii · rhythm · shell

The full spacing reference, measured from the real styles.css. Spacing is an 8-aligned scale (with 4/6 half-steps for tight groups); every value below is what the components actually use, so a new sport matches by reusing these, never eyeballing.

Base unit 8. Use 4 / 6 only inside a tight group (icon↔label, dot↔text, eyebrow→title). Everything else is a multiple of 4.

9 · Table in a card — one symmetric padding
  • Card padding is symmetric and comes from .pcard (16px) — top must equal bottom. Never hand-set a card's padding inline.
  • The table sits flush inside the card; its own cell padding (.dtable / .ptable) carries the internal rhythm, so the last row balances the header automatically — don't add extra padding to compensate.
  • If a card genuinely needs more room, that's a defined variant (and still symmetric), not a one-off number. Per-card inline padding is how cards drift out of sync.

Charts & graphs

data-viz palette · bars · line · timeline
Bar fills & the blue-usage rule
  • Single bars (vertical, horizontal, progress, stat) always use the one bar blue --sb-steel (#A3C9FF) — never the darker blues.
  • The darker blues are used only for comparisons — two or more things shown together in one strip (ball-in-play, stacked bar).
  • In a comparison, go light → middle → dark: --sb-steel (#A3C9FF) → --bar (#7FB2FF) → --bar-deep (#2B7FFF). Never jump straight to the dark blue — a 2-way comparison uses light + middle.
  • The lightest comparison blue is --sb-steel — the same blue as the plain bars. No separate light blue is introduced.
Bar track background is the gray token --bar-track (rgba(16,24,40,.06)). The primary CTA blue is never used on bars.
Horizontal labelled bars · .hbars / .hbrow / .hbfill (+ .hbmed median)
.hbrow.sel emphasises a row; the dashed .hbmed line marks the squad median. The label column auto-sizes to the longest label (+10px gap) via subgrid, so bars start flush — no dead gap for short labels, and every bar stays aligned.

Tables

.ptable (list) · .dtable (data)
Anatomy
  • Header — uppercase micro-caps (11px / 600 / .05em / text-soft) with a hairline bottom border. Sortable columns add .sortable + a chevrons-up-down icon (.sico).
  • Rows — airy padding, hairline separators. .prow rows are clickable: hover fill + a trailing chevron-right, and they open the right-side drawer (never a new page).
  • Cells — numbers right-aligned with tabular figures; secondary text in .tdet muted; status via .stag / .exc.
  • Variants — .ptable list table (identity + status, → drawer) · .dtable dense data table (group headers .grp + a bold .sumrow total) · .extable exercise breakdown.

The rule — every UI built on this system follows it
  • Always a circle — never a square or rounded-square button.
  • Always a filled play triangle (fill:currentColor, path M8 5v14l11-7z) — never an outline / stroked icon.
  • Semi-transparent dark chip rgba(17,24,39,.55) over media; hover darkens to .72, active scales 96%.
  • Centre it on a media box with .thumb .playbtn (absolute, margin auto). The system never draws its own play control.
